# 纯前端架构、模型接入和交互界面

## 入口与模块

应用由 TypeScript、Vite、HTML/CSS 组成，使用 npm 管理依赖。`index.html` 加载 `src/main.ts`，生产构建生成静态 `dist/`，无需后端。原 Python 包、CLI 和 `/api/*` 接口已移除。

`index.html` 包含起卦与原理两个视图，由 `src/main.ts` 根据 `#cast`、`#method` 切换可见性。切换只隐藏已有 DOM，不重建表单、不重新起卦、不发出模型请求，问题、卦象、解读和配置保留在当前文档内存；正在进行的解读继续执行。URL 不存放用户数据，刷新后清空输入与结果。哈希导航支持前进、后退及直接打开原理视图，无需服务器路由回退，兼容 Pages 子目录。导航同步更新页面标题、`aria-current` 和可见视图标题的键盘焦点。原理视图含三钱数值与概率、动爻图示、乾初爻变姤示例、0–6 个动爻的取辞表、实现边界和原典链接。

| 文件 | 职责 |
| --- | --- |
| `src/divination.ts` | 校验语料、三钱起卦、本卦与之卦计算、取辞和原典结构。随机函数显式传入。 |
| `src/config.ts` | 解析 YAML 并校验运行设置和提示模板。 |
| `src/interpretation.ts` | 构造提示、验证端点、调用浏览器 fetch、解析 SSE、处理模型失败。fetch 可注入供离线测试。 |
| `src/main.ts` | 装配语料与配置，管理页面状态、随机源、输入、卦画、经传和流式 Markdown。 |
| `src/style.css` | 桌面与窄屏布局、卦画与经文样式。 |

`data/zhouyi.jsonl`、`config/settings.yaml`、`config/prompts.yaml` 通过 Vite raw import 进入构建产物。只打包正式语料，不发布 `data/` 内原始下载归档。修改配置或语料后重新构建，不在运行期访问服务器文件系统。

```text
输入问题 → 浏览器随机生成六个爻值 → 计算本卦、动爻、之卦
                                  → 查询打包语料并选取经文 → 显示卦画与经传
用户输入模型端点、模型名称和密钥 → 点击请求解读 → 直连模型 → 流式显示思考和正文
```

## 随机与数据约定

页面用 `crypto.getRandomValues` 获取随机字节，并取最低位作为公平钱币的 0/1。六次投掷各用三枚钱；核心算法只接收注入的随机函数。生产站点使用 HTTPS，本机开发使用 localhost/127.0.0.1。

计算、语料、序列化仍按初爻到上爻保存。卦画从第六爻向第一爻绘制。动爻附文字「动」及颜色标记，无动爻时之卦为 `null`。取辞规则与既有版本一致，保留主、辅、贞、悔与乾坤用辞。

页面保存本次问题与六个爻值。仅重新起卦会重新随机；模型重试沿用本次结果。编辑问题后禁用解读，直到重新起卦。请求期间禁用输入和重新起卦，避免结果串位。

## 配置与密钥

运行参数与提示模板继续使用 YAML。解析器使用 `yaml` 包，随后校验问题长度、超时、支持的生成参数和三个提示占位符。端点和模型名称默认留空，可在 YAML 设置公开默认值，页面输入优先。生成参数不允许覆盖 `model`、`messages`、`stream` 或添加凭据字段。

密钥由使用者在密码输入框填写，仅保存在页面内存。应用不读 `.env`、不使用浏览器持久存储、不记录密钥或问题。清除按钮删除页面持有的密钥，刷新清空本次输入和结果。不要通过 `VITE_*`、源码或 YAML 分发共享密钥。若未来需要项目统一密钥，应另行设计有认证与额度限制的代理。

## 模型传输

浏览器向用户填写的 API 根地址追加 `/chat/completions`，发送 Bearer 密钥与流式 Chat Completions 请求。仅允许 HTTPS 或本机回环 HTTP，拒绝 URL 凭据、查询参数及片段，并拒绝请求重定向。调用前在页面显示端点和发送内容说明。

跨域服务必须允许当前站点来源、POST 和 Authorization/Content-Type 请求头。CORS 由服务商控制，前端不能修复服务商的跨域设置。网络或 CORS 失败会显示可操作提示；本次迁移只使用模拟客户端验证，不声称任何实际服务商已验证兼容。

SSE 解析保留跨 chunk 的 UTF-8 与 CR/LF 边界，支持注释、多行 data 和 `[DONE]`。`reasoning_content` 与 `content` 分别展示；要求正常结束标记及非空正文。认证失败、限流、超时、截断、空正文和异常断流均保留原卦和经文，可显式重试，无自动重试。超时覆盖请求及整个流，并中止请求、关闭读取器。

Markdown-it 禁用原始 HTML；经文与输入用 DOM 文本节点显示。模型和提示模板不负责重算卦象、爻位或取辞。

## 离线与部署

首次加载需要静态文件，页面加载完成后起卦和查经无网络 I/O。当前不注册 Service Worker，不保证断网刷新可用。`npm run build` 先做严格类型检查再打包，`npm run preview` 可预览产物。发布整个 `dist/`；相对资源地址支持子目录部署。不要通过 `file://` 打开。

`.github/workflows/pages.yml` 在 PR 上运行检查，在 `main` 推送或手动运行时发布。构建任务使用 Node.js 24，执行 `npm ci`、`npm test`、`npm run build`，仅上传 `dist/`。发布任务依赖构建成功，并限制为 `main` 的非 PR 运行；`pages: write` 和 `id-token: write` 仅授予发布任务。官方 Actions 固定到提交 SHA。仓库管理员需先在 Settings → Pages 将 Source 设为 GitHub Actions；不需要个人访问令牌或模型密钥。页面继续使用相对资源和导航地址，可与账号已有个人站点共存。实际站点地址由部署任务返回，支持账号已有自定义域名。

## 验证

`npm test` 使用 Node 内置测试运行器与 tsx，测试不调用真实模型，也不需要密钥。Pages 工作流复用这一命令，将测试与类型检查作为发布前置条件；本地检查不能替代 GitHub 上实际运行和部署的验证。

- 枚举三枚钱的八种排列，验证 1:3:3:1 概率。
- 枚举全部 4,096 种爻值组合，检查本卦、翻转、之卦、取辞数量及经传关联；固定卦例覆盖 0–6 个动爻和乾坤用辞。
- 迁移时临时导出旧 Python 的全部结果，逐项比较 TS 返回的卦象、动爻、原文、主次和传文，4,096 组完全一致。该一次性对照不作为 Python 运行依赖保留。
- 模拟分字节中文 SSE、思考与正文、空文本、断流、认证失败、限流、超时和重试不变性。
- 使用 jsdom 执行打包后的页面，检查本地起卦无网络请求、Markdown HTML 转义、模型失败后原卦重试、修改问题后禁用解读、密钥清除及无持久存储；验证视图切换、前进后退保留状态且无额外请求，以及原理视图的直接访问和新文档状态隔离。DOM 模拟不替代实际浏览器的视觉与 CORS 验证。
- 发布前需在可用浏览器检查窄屏、键盘操作和模型配置；真实端点的 CORS 与生成字段支持需单独验证。

静态产物随附 `public/THIRD_PARTY_LICENSES.txt` 中的运行依赖许可；升级运行依赖时同步更新。
