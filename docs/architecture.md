# Python 包、模型接入和交互界面

## 首版入口

- `cyber-yi cast` 在终端输出六爻、卦象和所取经传。`--lines` 可复用已有爻值，`--interpret` 可显式调用模型。
- `cyber-yi serve` 在 `127.0.0.1` 提供网页。页面负责输入与展示，Python 服务端负责计算、查库和调用模型。

CLI 和 Web 共用 `divination.py` 中的起卦与取辞。两个入口装配配置、语料、随机源和模型客户端。离线结果和模型结果独立返回。

语料随仓库放在根目录 `data/zhouyi.jsonl`。入口将明确配置的语料路径传给核心逻辑。

```text
输入问题 → 生成六个爻值 → 计算本卦、动爻、之卦
                         → 查询本地语料并选取经文 → 显示卦画与经文
                                                  → 可选模型解读 → 显示对问题的解读
```

## OpenAI 兼容接口

- 通过已有 Python SDK 调用 `client.chat.completions.create`，把显式设置的 `base_url` 指向服务商的 API 根路径。CLI 读取非流式正文，网页把 DeepSeek 的 `reasoning_content` 和 `content` 分别向浏览器转发。兼容服务只返回 `content` 时，网页直接显示正文。[DeepSeek 思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/) · [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- 将端点、模型名、超时、有限重试次数和可选生成参数放在运行配置 YAML，把解读提示模板放在独立 YAML。由入口显式接收路径，用 `yaml.safe_load` 读取并验证类型和约束。API 密钥由入口使用 `python-dotenv` 从显式 `.env` 路径加载，保留进程已有环境变量。离线模式无需设置密钥。SDK 支持配置请求超时及自动重试，应用应统一配置重试行为以限制等待与重复调用。[OpenAI Python SDK 的重试与超时](https://github.com/openai/openai-python#retries)
- 用户提示用 `{{ question }}`、`{{ cast }}` 和 `{{ passages }}` 填入原问题、卦象与动爻、程序选出的占辞与传文。系统提示列出 0 至 6 个动爻的取辞规则，并以本次标明的取辞结果为解读依据。输出以文化体验和自我反思为定位。[提示词模板](../config/prompts.yaml)
- 界面从本地语料显示所取经传，并逐行展示本卦原典。存在之卦时可展开之卦原典。模型思考过程和正文分别渲染 Markdown，原始 HTML 按文本显示。[Markdown-it](https://github.com/markdown-it/markdown-it)
- 对缺少配置、超时、认证错误、限流或空文本分别给出简短状态。卦象和经文在模型失败时仍可阅读，重试解读复用原问题与六个爻值。调用远程模型前显示服务商或配置端点，说明问题与所选经文会发送给该服务。应用默认仅在当前进程或页面内保留问题与结果，日志省略问题、提示、回答与密钥。

## 界面选型

| 方案 | 用法与取舍 |
| --- | --- |
| CLI | 最快验证 Python 包、随机规则和离线语料。可用文本绘制六爻，适合开发和自动化。 |
| 纯静态网页 | 可做六十四卦浏览、离线起卦与图示。接入需要项目密钥的远程模型时，仍需一个服务端或已有模型代理。 |
| 本机网页加 Python 服务 | 推荐作为首个图形界面。用简单 HTML、CSS 和少量 JavaScript，服务端同源提供页面和接口。默认只监听本机，便于沿用 Python 实现和配置密钥。 |

本机网页建议有问题输入、起卦、查看卦象与经文、请求模型解读四步。用户发起新一卦时才重新随机。若提供公开部署，另行设计身份验证、调用额度和数据保留策略。

接口可以采用两次请求，便于先显示离线结果，并在网络失败后重试。

| 接口 | 请求和结果 |
| --- | --- |
| `GET /api/settings` | 返回问题长度限制、模型服务地址与解读可用状态。 |
| `POST /api/cast` | 生成六个爻值，返回本卦、动爻、可空的之卦、取辞与两卦原典。 |
| `POST /api/interpret` | 接收当前问题与六个爻值。服务端校验它们并重算卦象和经文，只返回本次解读或明确的失败状态。此入口也允许复现给定爻值的排卦。 |
| `POST /api/interpret/stream` | 使用相同输入，分别流式返回 `reasoning_content` 和 `content`。以逐行 JSON 传送，末尾给出 `done` 或 `error`。 |

浏览器把当前问题和六个爻值保留在页面状态中。服务端只接受长度为六、元素全为 `6`、`7`、`8`、`9` 的整数数组，以及长度受限的非空问题。服务端依据上述输入重算结果，卦名、经文、模型端点和密钥以服务端数据及配置为准。

## 卦画显示

从每卦的六位阴阳串即时画图，阳爻为一条实线，阴爻为两段断线。页面视觉上把上爻画在顶部、初爻画在底部，计算和序列化仍按初爻到上爻。使用同一组件展示 64 卦，有动爻时并排显示本卦和之卦。本卦的动爻附图形标记和文字，避免仅用颜色传达。图旁显示卦名、编号、上下卦以及可阅读的爻位说明。

首版用 CSS 画六条爻即可覆盖全部卦画。若需要可分享的独立图片，再由同一六位数据批量导出 SVG 或 PNG，避免维护两套卦画。

## 实现验收

- 枚举三枚钱的 8 种排列，核对起爻概率。枚举六爻的 4,096 种值组合，验证本卦、之卦和动爻均能查找、翻转规则一致。用已知卦例校验卦号与爻序，分别覆盖 0–6 个动爻的取辞分支及乾坤两处「用」辞。
- 验收通过本地语料路径离线查询。用同一组固定爻值验证 CLI 与网页显示的卦号、取辞和出处一致，并检查模型是否收到与所取经文对应的传文。
- 模拟模型正常响应、超时和空文本。验证重试解读时六个爻值和取辞不变，并验证离线查询全程无需调用网络。最后对用户配置的兼容端点做一次连通性验证，记录实际端点类型和支持的参数。
- 在窄屏和键盘操作下检查问题输入、动爻标记、无动爻时的单卦显示、失败状态和重试入口。
